전체 읽기 버튼이 문서 정보보다 위에, 맨 위에 존재

사진을 찍은 후 문서 읽기 화면이 꽉 차도록, 이상한 여백 만기지 말고

빠짐 확인 항목은 이름을 검토하세요! 버튼으로 이름 바꾸자



이 방식이 훨씬 더 현실적이에요. 기존 방식(종이+손을 실시간으로 같이 찍어서 추적)은 조명, 흔들림, 각도에 따라 오차가 크게 벌어지는 가장 위험한 기술 요소였어요. 그걸 "업로드 → 분석 → 패드에서 서명 → 출력"으로 나누면, 가장 어려운 컴퓨터 비전 문제 하나가 통째로 사라져요. 10시간 안에 구현하기에도 훨씬 안전한 선택이에요.

바뀐 전체 흐름
단계	내용
1. 업로드	계약서 전체 페이지를 촬영하거나 스캔해서 올려요
2. 문서 분석	독소조항 유무, 총 페이지 수, 서명이 필요한 페이지를 안내해요
3. 서명	패드에 펜으로 직접 서명해요. 위치나 글씨가 이상하면 진동으로 교정해요
4. 출력	원본 계약서에 서명을 합성해서, 출력 가능한 최종 파일로 돌려줘요

기존 계획에서 “0단계 촬영 안내”는 그대로 살아있어요. 다만 이제는 서명 페이지 하나만이 아니라 전체 페이지를 순서대로 찍어 올리는 용도로 바뀌어요. 각 장마다 "조금 왼쪽으로", "다음 장을 올려주세요" 안내는 똑같이 써요.

1단계: 업로드
페이지별로 촬영 안내를 반복해요. “1페이지 촬영 완료, 2페이지를 올려주세요.”
스캔 앱이나 PDF 파일이 이미 있으면 그대로 업로드도 받아요.
업로드가 끝나면 "총 7페이지를 받았습니다"라고 확인해 줘요.
2단계: 문서 분석 (사용자가 서명 전에 듣는 요약)

예전에 설계한 "빈칸 검출"과 "판단(법률 대조)" 로직을 그대로 재사용하되, 이제는 전체 문서를 한 번에 분석해서 요약으로 먼저 들려줘요.

"총 7페이지입니다. 3페이지에서 위약금 조항이 표준계약서와 다릅니다, 근거를 들을까요? 서명이 필요한 페이지는 1페이지와 7페이지입니다."

독소조항 유무: 지난번에 설계한 법률 규칙 엔진(표준계약서 대조, 수치 검사, 조항 패턴 검사) 그대로예요.
총 페이지 수: 업로드된 이미지/PDF 수.
서명 페이지: 빈칸 검출에서 "서명", “(인)”, "날인" 키워드로 이미 찾던 로직을 재사용해요. 다만 이제는 "페이지 몇의 어느 칸"까지 짚어줘요.
3단계: 서명 (패드)

여기가 가장 중요하게 다시 설계해야 할 부분이에요.

입력 방식

패드 화면에 Pointer Events(마우스·터치·스타일러스를 모두 받는 웹 표준)로 펜 궤적을 그대로 기록해요. 스타일러스를 쓰면 필압도 같이 잡혀요.

교정 로직 두 가지

위치 교정 (서명란을 벗어났는가)
2단계에서 찾은 서명란의 좌표(가이드 박스)를 패드 화면에 옅게 표시하거나, 안 보이는 사용자를 위해 화면에는 안내선만 그려두고 음성으로 먼저 알려줘요.
펜이 박스를 벗어나는 순간 진동 + "칸을 벗어났습니다"
다 그린 뒤 획 전체의 바운딩 박스가 가이드 박스를 벗어났는지 최종 확인해요.
글씨 품질 교정 (이상한 서명인가)
이전 "글씨 연습" 단계에서 모은 연습 서명 데이터(크기, 획 수, 소요 시간, 가로세로 비율)를 기준값으로 저장해 둬요.
실제 서명이 그 기준에서 크게 벗어나면(너무 빠르게 한 획으로 긋거나, 크기가 절반 이하로 찌그러지는 등) "다시 서명해 주세요"로 안내해요.
이 판정은 AI가 "느낌"으로 판단하지 않고, 획 수·크기·시간 같은 수치 비교로만 해요. 이게 이전에 설계한 “AI 맹점 → 규칙 기반 보완” 구도와도 맞아요.

진동을 주는 주체, 꼭 확정해 주세요.-->>> 진동 주체는 펜이 아니라 디바이스로 확정할게 패드겠지 아마

브라우저의 진동 API(Vibration API)는 안드로이드 태블릿/크롬에서는 동작하지만, 아이패드(iOS Safari)에서는 동작하지 않아요. 애플펜슬 프로의 자체 햅틱 기능은 iOS 앱에서만 쓸 수 있고 웹에서는 못 써요.
그래서 "패드"가 구체적으로 뭔지에 따라 구현이 갈려요.
안드로이드 태블릿 + 스타일러스: 웹 진동 API로 바로 가능해요. 가장 현실적이에요.
아이패드: 진동이 안 돼서, 대신 화면 테두리 색 변화나 소리로 대체해야 해요. 시각장애인에게는 소리가 사실상 필수가 돼요.
그래픽 태블릿(와콤 등) + 노트북 화면: 패드 자체에는 진동이 없는 제품이 많아서 확인이 필요해요.

해커톤에서 실제로 쓸 기기가 뭔지 알려주시면, 그에 맞춰 안내를 "진동"으로 할지 "소리+진동"으로 할지 정할게요.

4단계: 출력
1단계에서 전체 문서를 이미 파일로 갖고 있으니, 합성이 훨씬 쉬워져요.
서명 획 데이터를 투명 배경 PNG(또는 SVG)로 변환해서, 2단계에서 찾은 서명란 좌표에 정확히 붙여요.
모든 서명 페이지에 합성한 뒤, 최종 PDF로 내보내요. 인쇄도 되고 다시 제출도 가능해요.
마지막에 음성으로 확인해 줘요. “1페이지, 7페이지에 서명을 추가했습니다. 다운로드하시겠어요?”
기술 스택 변경 사항

빠지는 것: MediaPipe Hands로 종이 위 펜을 실시간 추적하던 부분. 가장 어렵고 가장 불안정했던 요소라 제거하는 게 맞아요.

새로 필요한 것:

다중 페이지 처리: PDF.js(기존 PDF 렌더링) 또는 업로드된 사진들을 묶어 PDF로 변환
서명 캡처: Canvas + Pointer Events
서명 합성·출력: pdf-lib로 좌표에 이미지 스탬프를 찍고 병합
진동: Vibration API (안드로이드 전제)
