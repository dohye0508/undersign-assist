# 2026-11-09 독립 재검토

종류 확장 구현을 맡지 않은 새 에이전트가 README와 읽기→판단 흐름을 검토하고, 실제 실패를 재현하는 테스트를 먼저 작성했다. 별도 검토로 앱의 비동기 상태와 설문·쓰기 안내도 확인했다. 외부 AI/API나 실제 개인정보 문서는 사용하지 않았다.

| 재현한 문제 | 변경 및 회귀 확인 |
|---|---|
| OCR 시급 5,000원이 AI의 15,000원으로 바뀌어 경고가 사라짐 | 원문값·항목 이름 일치 검사. 다른 줄/같은 줄 식비 전용과 없는 장소 생성도 거부하고 규칙 추출로 복귀 |
| 5천만원·1억5천만원·1.5만원·1만2천원 자릿수 오산 | 전체 금액의 단위 조합을 Decimal로 계산. 잘못된 구분자·역순 단위의 뒷부분만 읽지 않음 |
| 주 3일/주 24시간을 무시하고 월급을 주 40시간 기준 환산 | 명시되거나 추출된 주 근로시간을 우선 사용. 기존 환산식과 법령 기준값은 변경하지 않음 |
| 영수증의 환불/할인 금액을 결제 금액으로 읽음 | 구체적인 항목명을 전체 문서에서 우선 탐색. 일반 `금액`이 다른 항목의 접미어이면 제외 |
| 빈 청구금액 다음 줄 고객번호를 금액으로 가져옴 | 다음 줄이 별도 라벨이면 값으로 연결하지 않음 |
| 사진·답변 변경 중 이전 요청 결과가 새 문서 상태에 반영됨 | 요청 버전과 고정 입력 사본 사용, 중복 호출 공유, 폐기한 화면/이전 요청의 성공·오류 무시 |
| 설문지의 예/아니요를 개인정보 동의처럼 읽음 | 설문 질문을 그대로 안내하고 `응답`으로 구분. 실제 개인정보 동의 문항은 동의 안내 유지 |
| 빈칸·서명이 없는 영수증에도 재촬영 지시 | 이미 작성됐거나 읽기만 필요한 문서일 수 있음을 안내 |

검증 파일:

- `test_independent_review.py`: 값·판단까지 이어지는 독립 회귀 사례.
- `test_money_parse.py`: 금액 단위·소수·유효하지 않은 표현.
- `app/test/workspace_state_test.dart`: 의도적으로 응답 순서를 바꾼 비동기 테스트 8개.
- `app/test/document_type_workflow_test.dart`: 읽기 전용 문서와 설문 응답 흐름 4개.
- 기존 테스트와 `samples/document-types/` 실제 OCR 기록 192건을 다시 평가한다. 이 재평가는 OCR 재실행이 아니라 같은 인식 결과에 대한 최신 분류·추출 재생이다. CI에서는 별도로 실제 Tesseract 175건을 실행한다.

한계: AI를 실제 서비스에 호출하는 부하 시험은 아니며, 모의 응답으로 잘못된 값의 수용 여부를 검증했다. 모든 금액/서식 표현을 지원하는 것은 아니다. 증명서에 대상자와 발급자 이름이 함께 나오는 등 주체가 모호한 서식의 값 추출에는 추가 검증이 필요하다. 새 문서 표본의 OCR 항목값 오류 9건은 숨기거나 추정 보정하지 않고 샘플 보고서에 남겼다.

## 추가 검토: 페이지 혼합·인물 구분·판단 범위·출력

별도 에이전트 3명이 분류, 인물별 항목 추출, 실제 PDF 좌표를 나누어 검토했다. 부모 에이전트는 판단 완료 안내와 월급 환산의 누락 입력을 검토하고, 발견한 오류의 실제 OCR 재현 및 미리보기 일치를 확인했다.

| 재현한 문제 | 수정 |
|---|---|
| 제목이 잘린 위임장 뒤 개인정보 부록이 문서 종류를 바꿈 | 첫 실제 서식 페이지의 충분한 근거를 우선하며 표지는 건너뜀 |
| 제목 잘린 다른 종류의 서식이 함께 있어도 한 문서로 처리 | 본문만 있는 뒤쪽 서식도 충돌 검사. 서로 다른 계약 분야도 구분 |
| 작성 가이드 부록의 예시가 청구서 분류 근거가 됨 | 참고 페이지는 서식 분류 근거에서 제외 |
| 발급 대표자/보호자/담당자가 대상자/신청인으로 추출됨 | 항목별 허용 주체와 구역 제목 확인. 증명서에 대상자가 따로 있으면 신청인보다 우선하며, 빈 대상자를 신청인으로 대체하지 않음 |
| 임금 지급일이 임금으로, 보호자 연락처가 이름으로 추출됨 | 긴 라벨과 하위 항목의 소유 관계 확인. AI에도 같은 원문 소유 검사 적용 |
| 판단 기준 없는 문서를 검토 완료처럼 안내 | 지원 범위를 정하지 못했다고 명시. 신청서·작품요약서는 종류별 확인 항목 안내 |
| 근로시간 누락 시 주 40시간을 만들어 시급 환산 | 명시된 주 시간 또는 일 시간과 근무일이 있어야 환산. 없으면 환산 보류 안내 |
| 세로 서명이 PDF에서 왼쪽에 붙고 글씨가 위쪽에 붙음 | 고정 크기 칸 안에서 정렬. 글씨 완료 미리보기에도 같은 왼쪽 여백 적용 |

검증:

- 백엔드 전체 115개 테스트 통과(이전 81개에서 34개 추가). 다중 페이지 9개 테스트 안에 222개 변형 사례 포함. AI는 모의 응답으로 원문 근거 검사를 확인했다.
- 실제 PDF 바이트의 이미지 배치 좌표 검사 4개와 완료 미리보기 검사 2개 통과. 변경 Dart 파일 정적 분석 통과.
- `samples/review-round2/`: 직접 작성한 5묶음 × 정면/5도 기울기 = 10건, 이미지 16장. 실제 Windows Tesseract 5.5.0을 실행해 종류·재촬영·지정 항목값 조건 10/10 통과, 지정 항목값 8/8 일치. 같은 OCR에서 이전 분류 5/10 → 현재 10/10. 분류 외의 모든 글자 정확도를 측정한 수치는 아니다.
- 기존 확장 표본의 **저장 OCR 재생** 192건: 일반 분류 168/168, 실패 대조군 24/24, 지정 항목값 327/336. OCR을 다시 실행한 결과와 구분한다.
- 기존 656건의 **저장 OCR 분류 재생**: 일반 603/608, 새 분류 회귀 0. 이전 대비 33건은 영수증 지원에 따른 `unknown → receipt` 변경. 기존 일반 실패 5건은 유지되며 모두 저장된 재촬영 표시가 있다. 실패 대조군 48건의 재촬영은 저장 결과를 확인한 것으로 이번 재평가가 아니다.
- CI는 기존 실제 OCR 175건에 새 10건을 더하고, PDF·미리보기 6개를 자동 검사하도록 확장했다. Linux OCR 결과는 별도 artifact에 저장한다.

남은 일반 실패 5건: `everyday_originals/original_05/motion_blur`, `everyday_originals/original_06/sideways_desk`, `everyday_originals/original_08/motion_blur`, `originals/original_05/handheld`, `originals/original_05/screen_moire`.

한계: 새 사진은 합성 시험 자료이며 현장 촬영·임의 손글씨 전체를 대표하지 않는다. 익숙하지 않은 주체 접두어는 잘못된 사람을 선택하지 않도록 생략한다. 판단 수식·법령 기준값과 OCR 엔진 자체는 이번에 바꾸지 않았다.
