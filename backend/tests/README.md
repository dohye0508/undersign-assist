# 문서 분류 회귀 시험

분류는 OCR **이후**에 실행된다. 이 시험은 문서 종류와 뒤따르는 항목 추출·판단의 연결을 검증한다. 법률 기준이나 법령 데이터는 변경하지 않는다.

## 표본

- `fixtures/document_cases.json`: 직접 구성한 가상 한국어 서식 85개. 계약·임대차·차용증, 개인정보 동의, 가정통신문, 신청, 작품 요약, 알 수 없는 문서를 포함한다. 제목만 남은 문서, 개인정보 부록, 단어 반복, 교육자료·처리방침·수술 동의서도 구분한다.
- `fixtures/document_generalization.json`: 첫 개선 후 추가한 일반 상황 48개. 두 줄 제목, 문서번호, 작성 안내서, 제목 누락, 표지, 개인정보 동의가 섞인 신청서, 다른 종류의 문서가 함께 올라온 경우를 포함한다.
- `fixtures/document_ocr.json`: 저장소 `samples/` 사진 9개를 2026-10-29 로컬 Tesseract 5.5.0 한국어 모델과 기존 두 번 읽기 코드로 인식한 결과. 원본 파일 경로와 줄·좌표·페이지를 기록했다. `consent_school.png`와 `인곽.png`는 같은 양식이며 독립 표본으로 해석하면 안 된다.
- `app/test/fixtures/ocr_*_deployed.json`: 기존 배포 서버 OCR 3개. 깨진 글자와 누락된 표 머리글을 그대로 사용한다. 로컬 사진과 양식이 겹친다.
- 각 표본에 원문, 글자 사이 공백, NFD 한글, 보이지 않는 문자·구분자, 세 번 중복한 페이지를 적용한다. **145개 입력 × 5개 변형 = 725건**이며 서로 독립적인 725개 문서는 아니다.

## 실행

저장소 루트에서 백엔드 가상 환경의 Python을 사용한다. 정규 회귀 시험에는 Tesseract 실행 파일·네트워크·API 키가 필요 없다.

```sh
python -m unittest discover -s backend/tests -p "test_*.py" -v
python backend/tests/evaluate_documents.py --failures
python backend/tests/smoke_judge.py
```

평가 결과를 파일로 남기거나 같은 표본의 이전 결과와 비교할 수 있다.

```sh
python backend/tests/evaluate_documents.py --output work/current.json
python backend/tests/evaluate_documents.py --baseline work/baseline.json
```

Tesseract와 `kor.traineddata`가 있으면 합성 이미지 18개를 넓은 배치·좁은 배치로 각각 만든 뒤 실제 OCR을 거치는 36건도 실행한다. 사진은 메모리에만 생성한다. `--all`은 작성한 85개 사례 전체를 이미지로 시험하는 탐색용 옵션이며 OCR 엔진 버전에 따라 결과가 달라질 수 있다.

```sh
python backend/tests/smoke_ocr_documents.py --output work/ocr-evaluation.json
```

일반 촬영 조건은 다른 내용의 가상 문서 16개 × 아래 15개 조건으로 시험한다. 각 조건은 픽셀에서부터 실제 Tesseract를 실행하며, 분류뿐 아니라 원본 사진 밖으로 벗어난 좌표가 없는지도 검사한다. 생성한 이미지는 메모리에서만 다루고 결과 JSON에 OCR 글자·좌표·분류·처리 시간을 남긴다.

| 조건 | 재현 방법 |
|---|---|
| 기본 | 흰 종이, Pretendard 글꼴 |
| 기울어짐 | 5도 회전 |
| 저해상도 | 가로 600픽셀 축소 |
| 흐림 | Gaussian blur 1.5픽셀 |
| 그림자·낮은 대비 | 좌우 조명 구배와 대비 감소 |
| 원근 | 고정된 projective transform |
| JPEG 압축 | 품질 15 |
| 표 | 회색 가로선과 테두리 |
| 옆으로 촬영 | EXIF 없이 90도·270도 회전, 각각 별도 조건 |
| 거꾸로 촬영 | EXIF 없이 180도 회전 |
| 휴대폰 방향 정보 | 회전된 이미지에 EXIF 방향 태그 |
| 제목 잘림 | 사진 상단 제목 영역 제거 |
| 복합 열화 | 그림자·흐림·JPEG를 함께 적용 |
| 노이즈 | 고정 난수로 점 잡음 4000개 |

```sh
python backend/tests/stress_ocr_documents.py --output work/camera-after.json
python backend/tests/stress_ocr_documents.py --baseline-ref bfd3bc9 --output work/camera-before.json
```

`--profiles shadow sideways` 또는 `--cases g_labor g_consent`로 일부만 재현할 수 있다. `--baseline-ref`는 해당 로컬 Git 커밋의 OCR·분류 코드·규칙을 사용해 같은 사진 조건을 비교한다. 실행할 코드를 포함하므로 신뢰하는 커밋만 지정한다. CI에서는 대표 6개 문서 × 5개 조건 = 30건을 실행하고, 수동 실행의 `full_ocr_matrix`를 켜면 240건을 모두 실행한다.

## 일반 상황 추가 개선 비교

기준은 첫 개선 커밋 `bfd3bc9`이다. 추가 코드를 수정하기 전에 입력과 기대 종류를 구성했다. 수정에 사용한 개발용 자료이므로 별도 보류 검증 세트는 아니다.

| 시험 | 첫 개선 상태 | 추가 개선 후 |
|---|---:|---:|

| 실제 OCR: 반대 방향·180도·노이즈 | 24/48 | 48/48 |

| 기존 사진 9장 재인식 | 9/9 | 9/9 |
| 전체 텍스트와 변형 | 비교 미실행 | 725/725 |

수정 전 촬영 시험의 실패 62건은 다른 종류로 오분류한 것이 아니라 `unknown`으로 유보한 경우였다. 수정 후 240건에서 다른 종류로의 오분류와 좌표 범위 오류는 없었다. 지원하지 않는 영수증·처방전·견적서·의료 동의서의 기대 결과는 `unknown`이다.

위 비교는 두 번째 개선 시점의 결과다. 실제 사진의 모든 상황을 포괄하지 않으며, OCR 자체가 읽지 못한 내용을 분류기가 복구하지 않는다. 조명 보정은 픽셀 위치를 바꾸지 않고, 회전은 인식에만 적용한 뒤 상자를 원본 좌표로 돌린다. 당시 정상 문서는 2회, 낮은 신뢰도에서는 최대 5회 인식했다. 아래 추가 개선은 더 많은 조건부 재시도를 사용한다.

## 복합 장면과 본문 품질 평가

`realistic_ocr_documents.py`는 제목 분류만 맞는 경우를 성공으로 과장하지 않도록 **본문 CER**, 분류, 원본 좌표 범위, 재촬영 안내를 따로 기록한다. CER는 NFKC로 정규화하고 공백·문장부호를 제외한 영숫자·한글 문자열의 Levenshtein 거리 합 / 정답 글자 수 합이다. 읽기 순서가 바뀐 것도 오류에 포함한다. 원문 전사가 없는 저장소 이미지는 CER를 계산하지 않는다.

- `development`: 이번 OCR 조정에 사용한 문서 6종 × 11조건 = 66건.
- `holdout`: 위 6종과 내용이 겹치지 않는 10종 × 11조건 = 110건. 기존 회귀 자료에서 나눈 것으로, 외부에서 새로 수집한 독립 검증 자료는 아니다.
- `samples`: 저장소 이미지 8종 × 8조건 = 64건. 중복 이미지 `consent_school.png`를 제외하고, 기입된 계약서 `contract_filled.png`를 포함한다. 이 자료도 현장에서 새로 촬영한 사진 모음은 아니다.

| 조건 | 재현 내용 |
|---|---|
| tilted | 11~15도 기울기, 두 방향 |
| handheld | 원근 + 8~12도 기울기 + 그림자 + 축소 + 흐림 + 압축 |
| desk | 나뭇결 배경 위에 비스듬히 놓인 문서 |
| columns | 두 단에 나눠 배치한 본문과 전체 폭 제목 |
| grid | 음영이 번갈아 있는 표, 분리된 항목명과 값 |
| dark_screen | 검은 화면 위 흰 글자 |
| screen_moire | 가로 줄무늬 + 기울기 + 압축 |
| crease | 종이 접힌 부분의 좁고 강한 그림자 |
| pen_marks | 파란 체크와 붉은 원 표시가 겹침. 임의 손글씨 인식 시험은 아님 |
| body_blurred | 제목은 선명하고 본문만 심하게 흐린 실패 대조군 |
| clean | 해당 표본의 기준 이미지 |

조건별 수치는 스크립트에 고정돼 있다. 개발/분리 검증의 난수 seed도 다르다. `columns`, `grid`, `body_blurred`는 저장소 이미지 모드에서는 제외한다.

```sh
python backend/tests/realistic_ocr_documents.py --suite development --baseline-ref d9272ba --output work/scenes-before.json
python backend/tests/realistic_ocr_documents.py --suite development --require-correct --output work/scenes-after.json
python backend/tests/realistic_ocr_documents.py --suite holdout --output work/scenes-holdout.json
python backend/tests/realistic_ocr_documents.py --suite samples --output work/scenes-samples.json
```

`--baseline-ref`는 지정한 로컬 커밋의 OCR·분류 코드·규칙을 실행한다. 신뢰하는 커밋만 지정한다. 기본은 실패까지 기록하는 탐색 모드다. `--require-correct`는 분류·좌표·실패 대조군의 재촬영 안내가 기대와 다르면 종료 코드 1을 반환한다. 실제 촬영 자료가 아닌 이 행렬의 100%를 서비스 정확도로 해석하면 안 된다.

2026-10-29, Tesseract 5.5.0 `kor`, 직전 커밋 `d9272ba`와 같은 입력으로 비교한 결과:

| 항목 | 직전 구현 | 이번 구현 |
|---|---:|---:|
| 개발 장면 분류 (실패 대조군 제외) | 48/60 | 60/60 |
| 개발 장면 본문 CER | 37.50% | 7.88% |
| 내용 분리 장면 분류 (실패 대조군 제외) | 82/100 | 100/100 |
| 내용 분리 장면 본문 CER | 39.05% | 6.10% |
| 본문이 흐린 실패 대조군의 재촬영 안내 | 0/16 | 16/16 |
| 저장소 이미지 변형의 종류 분류 | 43/64 | 56/64 |
| 저장소 이미지 변형 중 재촬영 안내 없이 종류를 맞힘 | 43/64 | 51/64 |
| 새 장면의 좌표 범위 검사 | 240/240 | 240/240 |

개발/내용 분리 장면 160건에는 지원하는 서식 120건과 미지원 문서 40건이 들어 있다. 지원 서식의 분류는 90/120에서 120/120으로 개선됐다. 위 표의 분류 실패는 모두 `unknown`이며 다른 지원 종류로 잘못 확정한 사례는 없었다. 이미지 64건 중 12건은 재촬영 안내 대상이다. 따라서 56/64를 그대로 자동 처리 성공률로 해석하면 안 된다.

남은 문제는 `작품요약서.png`의 빈 표, `인곽.png`의 축소·원근·줄무늬, `참가신청서２.png`의 책상 배경·축소·줄무늬에 집중돼 있다. 빈 작품요약서는 원본 상태에서도 재촬영 안내가 발생한다. 이를 성공 표본에서 제외하지 않았다. 해당 작품요약서의 책상 배경 조건은 이전에 종류만 맞혔으나 이번에는 유보하는 회귀가 남아 있다. 재촬영 안내와 분류 유보를 정확한 본문 복구로 세지 않는다.

전처리는 책상 배경, 화면 반전, 작은 기울기, 표 선, 화면 줄무늬를 조건별로 처리한다. 재시도는 신뢰도가 개선되고 기존에 확실히 읽힌 글자가 크게 사라지지 않을 때 채택한다. 좌표는 문서 읽기 순서를 정한 후 원본 사진 위치로 역변환한다. 정상 사진은 2회, 어려운 사진은 최대 9회 OCR 호출을 사용할 수 있어 처리 시간이 늘어난다.

`TextBlock.confidence`는 엔진 신뢰도이며 보정된 정확도 확률이 아니다. `/api/read`는 본문 근거가 부족한 페이지를 `needs_review`, `review_pages`(0부터)로 알리고, 이 경우 AI 항목 추출을 생략한다. 앱의 화면과 음성은 해당 페이지 재촬영을 안내하며 검토·쓰기·서명을 진행하지 않는다. `/api/judge`도 이 상태의 문서를 422로 거절한다. 예전 응답에는 새 필드가 없어도 앱이 읽을 수 있다.

이 판정은 보수적이다. 글자가 적은 빈 서식이나 복잡한 표도 재촬영 대상으로 잡힐 수 있다. 가림·반사로 완전히 사라진 내용, 임의 손글씨, 강한 원근, 세 단 이상의 편집을 모두 복구하거나 탐지하는 기능은 아니다. 영문 이메일·작은 글씨도 오류가 남는다. Google/Groq 실서비스 호출은 이번 측정에 포함하지 않는다.

CI는 기존 촬영 30건과 복합 장면 36건을 실제 Tesseract로 실행한다. 수동 전체 실행은 기존 240건과 내용 분리·저장소 이미지 평가를 추가한다. Flutter 화면 검사는 웹 플랫폼에서 실행한다(`flutter test --platform chrome test/read_quality_test.dart`).

## 저장된 샘플과 빈 표·복합 회전 개선 (추가)

이제 이전 촬영 행렬과 추가 상황을 `samples/regression/`의 **656개 JPEG**로 보관한다. `samples/index.html`에서 원본 출처, 조건, 정답, 변경 전후 본문, 재촬영 요청, 남은 실패를 확인할 수 있다. [샘플 구성과 재실행](../../samples/README.md), [수치와 남은 실패](../../samples/regression/results/README.md)를 참조한다. 평가 시 이미지 해시를 검사하며 생성과 평가를 분리한다.

추가 처리는 다음과 같다.

- 넓은 어두운 책상에 놓인 밝은 문서의 영역을 먼저 찾아 읽고, 모든 글자 좌표를 원본 사진으로 옮긴다. 그림자 때문에 종이 일부만 밝은 경우 잘못 자르지 않도록 경계 바깥을 검사한다.
- 90도 회전과 작은 기울기가 동시에 있는 사진은 각 회전 후보 안에서 기울기를 보정한다. 회전 전후에 보정이 두 번 생겨도 역변환을 순서대로 적용한다.
- 읽기 품질이 낮은 표는 긴 선과 눈금을 제거하고 글자 영역을 분리·확대해 다시 읽는다. 전체 밝기 기준으로 실패하면 국소 밝기 기준도 사용한다. 이미 정상으로 복구된 빈 양식은 추가 처리로 덮어쓰지 않는다.
- 빈 양식의 여러 항목은 짧더라도 읽기 근거로 인정한다. 제목만 남은 사진, 기호뿐인 결과는 재촬영 대상으로 유지한다. 사진이 옆으로 누워도 서로 다른 본문 줄을 구분한다.

이 경로는 OpenCV headless를 사용하므로 백엔드 의존성을 다시 설치해야 한다. 정상 사진은 기존 2회 OCR 경로를 사용하고, 어려운 사진은 조건에 따라 최대 14회 호출할 수 있다. 이번 성능 수치는 인식 품질이며 응답 시간 단축을 보장하는 수치가 아니다. Google OCR 경로는 별도로 보존했으며 실서비스 API를 호출해 검증하지 않았다.

`check_sample_geometry.py`는 저장된 책상 사진의 OCR 좌표를 독립적으로 변환한 제목 마스크와 비교한다. 단순히 사진 안에 들어오는지 외에 실제 제목 위치와 겹치는지도 검사한다. CI에는 빈 양식, 멀리 촬영한 문서, 회전·기울기, 본문 소실, 극단적 축소와 좌표 검사를 추가했다.

## 규칙 수정

`backend/app/rules/doc_types.json`의 `classification`을 수정한다.

- `titles`: 첫 페이지 앞부분에서 제목으로 인정하는 표현.
- `groups`: 같은 의미의 표현 묶음. 여러 번 나오거나 동의어가 겹쳐도 묶음당 한 번만 센다.
- `required_all` / `required_any` / `required_sets`: 제목 없이 본문으로 분류할 때 필요한 근거. `required_sets`는 목록 중 하나의 모든 근거를 갖추면 된다. 제목이 잘린 동의서도 목적·항목·보유 기간·동의의 조합으로 판단한다.
- `min_groups`: 제목 없는 문서에서 필요한 최소 근거 묶음 수.

`type_scores`는 제목 10점과 근거 묶음당 2점을 더한 진단 값이다. 출현 횟수나 확률이 아니며, 혼합 서식 분기 때문에 최고 점수 종류와 최종 종류가 다를 수 있다. 기존 API의 자료형과 종류 이름은 유지한다. `DocumentClassifier.classify()`의 `reason`으로 분기 이유를 확인할 수 있다.

제목이 둘 이상 충돌하거나 본문 근거 점수가 같은 경우 `unknown`으로 남긴다. 짧은 개인정보 문구가 있다고 주 문서 종류를 바꾸지 않는다. 의료·행사 참가 동의는 개인정보 동의와 별개이며, 현재 지원하지 않는 종류는 `unknown`으로 남긴다.

통신문 뒤의 회신 신청서, 신청서 뒤의 작품요약서, 개인정보 부록은 허용한다. 근로계약서와 가정통신문 또는 서로 다른 계약 분야가 함께 올라오면 `conflicting_documents` 사유로 유보한다. 같은 종류의 별개 문서 둘을 항상 구분하는 기능은 아니다.
