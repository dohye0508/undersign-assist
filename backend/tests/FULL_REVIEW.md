# 독립 에이전트 종합 검토 (2026-11-09)

기준 커밋 `ed3e752`에서 새 에이전트 3명이 프론트/접근성, 백엔드/API/운영 경계, 문서 근거/작성/출력을 나눠 검토했다. 통합 담당은 API 응답 무결성, 전체 테스트 누락, 배포 검증을 확인했다. 확인한 결함은 재현 검사와 함께 수정했다. 일반 사진의 OCR 정확도 개선 실험과는 별도 검토다.

## 실행한 검사와 CI

- 백엔드 전체 unittest 및 API multipart, AI 비정상 응답, 스트리밍 크기 제한, 판정 근거 경계 검사. `pip check`로 설치 의존성 충돌 확인.
- 앱 전체 정적 분석과 네이티브 테스트. 이전 CI에서 빠져 있던 설정·프로필 저장·받아쓰기·진동 규칙·시작 화면·진행 표시·체크박스도 포함한다.
- Chrome 위젯/카메라 수명 검사. `@TestOn('browser')` 파일을 CI에서 자동 검색하므로 새 브라우저 검사가 고정 파일 목록에서 누락되지 않는다.
- 기존 PDF 좌표·회전·서명 배치·미리보기와 실제 PDF 렌더 결과 검사도 계속 실행한다.
- 실제 localhost FastAPI와 Dart ApiClient로 한 장/두 장 읽기, 판단, 쓰기 확인, 손상 사진 400, 재촬영 문서 422를 재검증했다. 합성 문서와 실제 Tesseract를 사용했고 외부 AI는 껐다. 검증 서버는 종료했다.
- 배포 CI는 HTTPS API 주소 설정과 전체 analyze를 확인한다. 백엔드 CI에는 Docker 이미지 빌드, localhost health, 한국어 OCR 데이터, 컨테이너에 보낸 합성 사진의 실제 읽기 검사를 추가했다.
- 기존 실제 OCR 회귀와 실패 사례를 보존하는 경계 측정도 유지한다. 측정 단계의 성공이 모든 OCR 항목의 정확도 100%를 뜻하지 않는다.

최종 실행 수와 성공 여부는 해당 커밋의 Actions 로그를 기준으로 확인한다. 로컬 브라우저 테스트는 Flutter CanvasKit 리소스 404 제약 때문에 Linux Chrome CI에서 검증한다.

## 실행 방법

```sh
python -m unittest discover -s backend/tests -p "test_*.py" -v
python -m pip check
cd app
flutter analyze
flutter test
flutter test --platform chrome test/read_quality_test.dart test/frontend_recovery_test.dart test/camera_lifecycle_test.dart test/frontend_audit_test.dart test/fill_accessibility_test.dart
```

실제 로컬 연결 검사는 [API_REVIEW.md](API_REVIEW.md)의 실행 방법을 따른다. 브라우저 전체 파일 탐색 명령은 `.github/workflows/pages.yml`에 있다.

## 검증 한계와 운영 과제

- 브라우저 테스트는 카메라 권한·스트림·TTS를 모의한다. 실제 기기의 펜, 카메라, TalkBack/VoiceOver 음성·제스처, 모든 브라우저를 검증한 것은 아니다.
- 실제 클라우드 AI/Google OCR와 공급자 장애를 호출하지 않았다. 외부 응답 실패는 모의 HTTP로 검증했다.
- 공개 API에는 사용자 인증·호출 빈도 제한·동시 OCR 작업 수 제한이 없다. 이번 크기 제한은 전체 남용/서비스 거부 방어 또는 침투·부하 검증을 대신하지 않는다.
- 프로필은 브라우저 localStorage에 남는다. 암호화된 저장소나 여러 사용자의 계정 격리를 제공하는 설계는 아니다.
- 법령 자료 전체의 최신성·실제 계약의 법적 유효성, 서명의 본인 여부를 인증하는 검토가 아니다.
- Render 운영 백엔드는 수동 재배포가 필요하다. CI 컨테이너 성공과 저장소 푸시를 운영 반영으로 간주하지 않는다.
