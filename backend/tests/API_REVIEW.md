# 프론트엔드·백엔드 연결 검증

OCR 성능 조정과 분리해 HTTP 계약, 업로드, 오류 뒤 복구, 음성 안내를 검증했다. OCR·분류·추출·판정 엔진은 이번 변경에 포함하지 않는다.

## 확인하고 수정한 오류

| 재현 상황 | 수정된 동작 |
|---|---|
| 연결 또는 응답 본문이 끝나지 않음 | 요청 전체 3분 제한과 클라이언트 종료. 로딩 해제 후 재시도 가능 |
| HTTP 200의 빈 객체/HTML/잘못된 JSON/페이지 누락 | 정상 읽기·판단 결과로 채택하지 않고 응답 오류 안내 |
| 파일 문제도 모두 서버 확인 안내 | 400/413/422의 사용자 안내를 화면·음성에 보존. 서버 내부 예외나 검증 입력 배열은 노출하지 않음 |
| 빈 사진·손상 사진이 502이고 내부 경로가 응답에 포함됨 | OCR 실행 전에 400으로 거절. OCR 서비스 실패는 내부 예외 없이 502 |
| 사진 일부만 검증·처리되거나 파일 핸들이 남음 | 배치 전체 검증 후 OCR. 최대 10페이지/장당 10MiB/합계 50MiB, 성공·실패 모두 업로드 닫기 |
| 읽기 불가 사진으로 쓰기 확인 성공 안내 | 422 재촬영 안내, 외부 손글씨 AI 호출 생략 |
| 빈 문서·잘못된 페이지/좌표/원문 행을 판단 | 요청 경계에서 422로 거절. 기존 단일 페이지와 원문 행 -1 호환 유지 |
| 읽기·판단 재시도 후 음성이 없음 | 성공 요약 또는 다음 질문과 실패 안내를 다시 알림 |
| 답변 전송 실패 후 재시도하면 답 바꾸기가 사라짐 | 선택한 답을 유지하고 재시도 후 변경 가능 |
| 사진 선택/읽기 실패로 일부 파일만 들어가거나 가져오는 중 분석됨 | 배치 읽기 완료 후 추가. 실패 안내와 재선택 제공, 가져오는 중 분석·촬영·중복 선택 차단 |
| 검토 미완료·읽지 못한 항목이 있어도 '특별히 확인할 것이 없음' | 실제 finding 종류에 따라 미완료/원문 확인/정보 안내를 구분 |

## 검증 범위

- 백엔드: 실제 HTTP/multipart TestClient 검사 23개 추가, 전체 190개 통과. HTTP 검사는 OCR/AI만 모의하며 외부 API를 호출하지 않는다.
- 앱 API: 14개 테스트. 순서가 있는 multipart, 한국어 응답, 오류 상태, 비정상 응답, 페이지 참조, 시간 초과, 재시도와 연결 종료를 확인한다. 기존 상태 테스트 8개와 함께 통과했다.
- 검토 결론: 실제 백엔드가 생성한 가상 unknown/receipt 응답을 포함한 5개 테스트.
- 브라우저 화면: 재시도 음성, 답 변경, 사진 선택 실패, 배치 실패, 가져오는 중 분석 방지, 미완료 안내의 8개 위젯 테스트를 CI에서 실행한다. Windows의 로컬 브라우저 테스트는 CanvasKit JS/WASM 404로 앱 실행 전 멈춰 Linux CI를 확인한다.
- 실제 연결: 임시 localhost FastAPI와 실제 Dart ApiClient로 사진 한 장, 두 페이지, 판단, 쓰기, 손상 사진 400, 재촬영 문서 422를 확인했다. 합성 사진만 사용했고 Tesseract를 실행했으며 외부 AI는 비활성화했다. 검증 서버는 종료했다.
- 임시파일: Windows에서 1MiB 초과 multipart가 디스크로 스풀되는 것과 성공/실패 후 닫힘·삭제, 프레임워크의 중복 close까지 확인했다. 사진을 언제나 메모리에서만 처리한다는 이전 설명을 바로잡았다.

## 재현

```sh
python -m unittest discover -s backend/tests -p "test_*.py" -v
cd app
flutter test test/api_client_test.dart test/workspace_state_test.dart test/judgement_summary_test.dart
flutter test --platform chrome test/frontend_recovery_test.dart
```

로컬 연결 시험은 `GROQ_API_KEY`를 빈 값으로 설정하고 `OCR_PROVIDER=tesseract`로 백엔드를 `127.0.0.1:8016`에 실행한 뒤 아래 명령을 사용한다. 외부 공개 주소에 테스트를 보내지 않는다.

```sh
flutter test --dart-define=RUN_LOCAL_API=true --dart-define=API_BASE=http://127.0.0.1:8016 test/api_integration_test.dart
```

실제 카메라 하드웨어·모든 브라우저의 파일 선택기·실제 음성 출력을 전부 시험한 것은 아니다. UI 검사는 카메라·파일 선택기·TTS를 모의한다. Render 백엔드는 별도의 수동 재배포가 필요하며 저장소 푸시만으로 운영 서버 반영을 주장하지 않는다.
